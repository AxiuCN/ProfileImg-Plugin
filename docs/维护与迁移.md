# 维护：初始化 / 迁移 / 更新 / 锁

> 常驻规范见 [`../AGENTS.md`](../AGENTS.md)；动迁移、下载更新、锁或 Git 调用前读本文。

## `#图库初始化`（幂等）

```
建目录 + initMap / ensureGalleryConfigFile / ensureManagerConfigFile
  → refreshGalleryConfigFile() 刷注释 → autoRegisterUnregisteredRepos() 补登记
  → syncProfileImgSrc() 从配置注册 miao → 报告布局状态 / 源列表 / 待登记 / 未注册（changed 时提示重启）
```
与启动流程同一套逻辑，随时可重跑；legacy 布局下引导 `#迁移图库`。

## 旧布局 → 多源迁移

```
#迁移图库（legacy）→ precheckMultiSrc() 预检报告 → #确认
  → 备份配置（map.json / miao profile.js / gallery_config.yaml → gallery/backup/migrate-<时间>/）
  → 移除根 junction 并改建成真实默认图库 → 搬迁 default 内容
  → 清理主仓库来源副本（来源不可直读则保留，避免丢图）
  → 默认图库文件名规范为 default 段位（原名进「」备注段）→ 保持 .bak 屏蔽状态
  → 清理聚合层角色级 junction → syncProfileImgSrc() → 强提示立即重启
```

- **强制迁移**：旧 junction 布局一律由 `guardLayout()` 拦截并提示 `#迁移图库`（不做双模式兼容）
- **junction 判定只走 lstat**（损坏 junction 的 `existsSync` 为 false，必须先识别出来）
- **根 junction 移除失败即中止迁移**（否则文件会顺着 junction 写进聚合目录）；角色级 junction 失败只告警
- 迁移可重复执行，失败提示里带「可重跑 #迁移图库」
- **不丢同源文件**：搬迁 default 时同名文件大小相同视为重复跳过，**大小不同则把源版本另存为 `<名>.conflict` 并告警**（`.conflict` 不是 miao 认的后缀，不污染图库）

## 下载 / 更新 / 屏蔽

```
#下载第三方图库 <URL> [目标目录] → clone（非 Git 且非空则拒绝覆盖）→ addThirdPartyRepo 登记
  → buildSyncReport(syncProfileImgSrc()) 生成提示；probeRepo 提示结构（tier / 平铺 / 不支持需整理）
#下载主图库 / #下载屏蔽图库 → 逐仓库 clone → syncProfileImgSrc()（提示重启）
#主图库更新 / #主图库强制更新 → 逐仓库 pull/reset → 同步源列表；屏蔽图库同理
#更新第三方图库 [图库名] → 逐仓库 pull（只读源，不复制；remoteUrl 为空的本地源跳过）→ 同步源列表
#删除第三方图库 <名> → 移配置 → 删仓库目录 → 重新注册源列表

#自动更新（统一 cron，默认 0 30 5 * * *）→ 主图库 → 屏蔽图库 → 第三方图库 → 图库源同步
#  逐类开关：gallery.autoUpdate.enabled / repos[].autoUpdate / blocked.enabled / thirdPartyUpdate.enabled
#  单步失败不中断后续，末尾 notifyMaster 汇总

屏蔽/启用：main 段（1~9999）移入/移出 blocked-character；default 段（10001+）改/去 .bak；第三方源不参与序号
```

- 更新失败必须判 `result.ok` 且**不记版本**（否则下次以为已更新）
- 第三方源屏蔽**不具备持久性**（`#强制更新第三方图库` 的 `reset --hard` 会抹掉 `.bak`）；源内**唯一**可见图片被屏蔽后该源不再可直读（被屏蔽的图本来就读不到，不影响屏蔽效果）

## 并发与锁

- 第三方图库**下载 / 更新 / 删除**统一 `thirdPartyLockId()`；上传 / 删除 / 屏蔽 / 启用 / 重命名在改动主仓库或屏蔽图库文件时用 `mainRepoLockIdForPath()` + `acquireLocks()` 取**同一把仓库锁**（默认图库不是 Git 仓库，不加锁）
- 锁被占即拒绝并提示「正在更新，请稍后再试」；`acquireLock` 用 `wx` 原子创建，过期 / 损坏的锁可接管
- **上传序号在写盘前取**：`_getNextSeq()` 必须在 `fetch` 与压缩（都含 await）之后、`writeFileSync` 之前调用，取号与写盘之间不得有 await（否则并发上传撞同一个 `n`，删 / 屏蔽会打错目标）

## Git 调用规范

- 一律 argv 参数化：`gitExec(gitDir, [args…])` / `gitExecAsync(...)` 走 `execFile`，**不得拼 shell 字符串**（外部值来自用户输入与远程分支名，远程可返回含 `&` 的引用名）
- 地址与分支名过白名单（`isSafeRemote` / `isSafeRefName`，拒绝 `-` 开头以避开参数注入如 `fetch --upload-pack`）
- 主图库下载走**分支探测**（`detectRemoteBranchAsync`），不硬编码 `main`

## 面向用户的文案

- 重启提示一律 `restartHint()`（只说「重启 Yunzai」，不给 pm2 / node / 服务脚本等具体方式）；确有额外后果时（如迁移后自定义图库的图暂不可见）在其后追加一句
- 同步结果统一 `buildSyncReport()`（下载 / 更新 / 删除共用）
